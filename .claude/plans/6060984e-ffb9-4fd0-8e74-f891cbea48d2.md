# Plan: Features 43 & 44 — Retain delisted symbols + price history, survivorship audit

## Context & scope

The `universe` package (`packages/universe`) already implements features 40
(monthly top-N universe), 41 (point-in-time `universe_membership` intervals) and
47 (liquidity floor). This task completes the survivorship-integrity story:

- **Feature 43** — *System retains delisted symbols with their full price
  history, which returns them in any window covering their listed period.*
  A price store that holds only current members would silently drop every
  symbol that later leaves the universe — the exact survivorship bias §4.3 is
  written against. The store must retain price bars for **all** symbols, and a
  window query must return a delisted symbol whenever the window covers the
  period it was listed.
- **Feature 44** — *System emits a survivorship audit report counting delisted
  symbols present in each historical window.* An auditor must be able to read,
  per window, how many (and which) symbols the universe has since dropped but
  whose price history is still present — the names a current-universe-only view
  would silently lose.

Both are `plugin="universe"`. The package is **stdlib-only by design** (it is
part of the data spine and must import without third-party wheels), so the new
modules stay stdlib-only and reuse the package's own `DailyBar` shape — NOT
`feature_store.bars.DailyBar`, which is a different package with its own
boundary (the existing feature-40-vs-feature-57 split).

### What is NOT in scope
- Not the `contract.MarketWindow` — it holds only `t` + `universe` (a symbol
  tuple) and must not be given price data or a `bars()` method.
- Not the Postgres migration itself (feature 108 is `core`) — only the store's
  own idempot

ent `CREATE TABLE IF NOT EXISTS` schema, which is the package's existing
  pattern. The spec references the tables from feature 108 to satisfy coverage.
- Not feature 42's full decision-time resolution of the *window's* universe
  (that is host-side); we add `UniverseService.resolve(when)` for membership as
  of `t`, which feature 43 depends on and feature 44 consumes.

## Design

### New module: `packages/universe/src/universe/history.py` — feature 43 price store

A `PriceHistoryStore` that retains daily price bars for every symbol and answers
window queries. Mirrors `store.py`'s structure (schema string, `connect`,
idempotent tables, explicit column lists, stdlib sqlite).

```python
@dataclass(frozen=True)
class PriceBar:
    symbol: str
    date: dt.date
    close: float          # validated > 0 and finite (a non-positive price has no log return)
```

`PriceHistoryStore` (bound to a `DATABASE_URL`):
- `ingest(bars)` — upsert price bars keyed by `(symbol, date)`; idempotent per
  bar, so re-ingesting a restated day replaces it (the ingest layer owns
  exactly-once; the store takes the freshest value, matching
  `median_dollar_volumes`' collapse-to-last semantics).
- `symbols_in_window(window_start, window_end)` → `tuple[str, ...]` — every
  symbol with at least one bar in the inclusive window, **sorted ascending**
  (feature 43's stable-ordering acceptance bullet; the ordering every
  downstream reduction consumes).
- `bars(symbol, window_start, window_end)` → ordered per-symbol bars, for the
  audit and for any consumer that needs the actual prices.
- `listed_range(symbol)` → `(first_date, last_date)` — the span a symbol was
  listed, so "any window covering its listed period" is checkable.
- `count_symbols_in_window(...)` — the scalar the audit aggregates.

Schema (matches the spec's `universe_price_history` table):
```
CREATE TABLE IF NOT EXISTS universe_price_history (
    symbol  TEXT NOT NULL,
    date    DATE NOT NULL,
    close   REAL NOT NULL,
    PRIMARY KEY (symbol, date)
);
```

### New module: `packages/universe/src/universe/audit.py` — feature 44 survivorship audit

Pure functions over the price history and the membership intervals. The audit's
load-bearing idea: **a delisted symbol is one whose membership interval has
closed** (`valid_to is not None`) — the store's own record of "left the
universe" — and it is *present in a window* when its retained price history has
a bar inside that window. Counting those per window is the survivorship number
feature 44 names.

```python
@dataclass(frozen=True)
class WindowAudit:
    month: str
    window_start: dt.date
    window_end: dt.date
    delisted_present: tuple[str, ...]   # sorted; the names dropped but still in history

    @property
    def delisted_count(self) -> int: ...
```

- `delisted_symbols(intervals)` → `set[str]` — symbols with a closed interval.
- `audit_window(history, intervals, month, window_start, window_end)` →
  `WindowAudit` — the delisted symbols whose price history intersects the
  window.
- `survivorship_audit(history, intervals, months)` → `tuple[WindowAudit, ...]`
  — one per monthly window, in month order. `months` may be omitted to derive
  from the builds on the store; each window's bounds come from the build's
  trailing window (the same `_window_bounds` rule), so the audit's windows are
  the universe's own, not a re-derived guess.
- `render_report(audits)` → `tuple[str, ...]` — one line per window:
  `"2026-05 [2026-04-01, 2026-04-30] delisted=2: BBBUSDT, CCCUSDT"` (or
  `delisted=0` with no names).

### Persistence: extend `store.py`

- Add `universe_price_history` and `universe_survivorship_audit` to `_SCHEMA`
  (idempotent `CREATE TABLE IF NOT EXISTS`), following the existing pattern.
- `persist_price_history(bars, database_url)` — upsert bars.
- `persist_survivorship_audit(audits, database_url)` — replace the audit table
  atomically inside one transaction (same wholesale-replace pattern as
  `_recompute_membership`, so a restated price history re-derives the audit).
- `load_survivorship_audit(database_url)` → `tuple[WindowAudit, ...]`.
- A convenience `ingest_and_audit(...)` that ingests price bars and re-derives
  the audit from all builds + the full price history in one transaction — the
  one-call path a live ingest uses, mirroring how `persist_monthly_universe`
  already re-derives membership.

### Service facade: extend `service.py`

- `UniverseService.resolve(when, database_url=None)` → `tuple[str, ...]` — the
  symbols tradable as of `when`: every membership interval whose
  `covers(when)` holds, sorted. This is feature 43's "resolves membership as of
  a decision time" and feature 42's intent, surfaced through the same facade the
  rest of the package uses.
- `UniverseService.ingest_prices(bars, database_url=None)` → count.
- `UniverseService.price_history` → a `PriceHistoryStore` bound to the service's
  `database_url`, so window queries route through the same store the builds use.
- `UniverseService.survivorship_audit(months=None, database_url=None)` →
  `tuple[WindowAudit, ...]` and `.render_survivorship_report(...)`.

Wire `build_universe_service` to construct a `PriceHistoryStore` alongside the
config (no new env needed; it reads the same `DATABASE_URL`).

### Package exports: `__init__.py`

Export `PriceBar`, `PriceHistoryStore`, `WindowAudit`, `survivorship_audit`,
`render_report`, `ingest_and_audit`, `persist_price_history`,
`load_survivorship_audit`, and the new service methods — matching the existing
flat `__all__`.

## Tests

New suites under `packages/universe/tests/` (the package's own test scope):

- `test_history.py` — retention & window queries:
  - a symbol delisted after a window still returns from a query whose window
    covers its listed period; a window entirely after the last bar does not;
  - `symbols_in_window` is sorted and de-duplicated;
  - ingest is idempotent per `(symbol, date)` and a restated close replaces;
  - `listed_range` matches the bars; non-positive/non-finite close rejected;
  - persistence round-trip and store isolation (mirrors `test_store.py`).
- `test_audit.py` — the survivorship counts:
  - a window containing a closed-interval symbol with price bars counts it;
  - a closed-interval symbol with **no** price bars in the window does not;
  - the report line format and `delisted=0` for a clean period;
  - **non-zero across a period known to contain delistings, zero across one with
    none** (feature 44's discriminator bullet);
  - audit windows equal the builds' trailing windows;
  - restating price history re-derives the audit (wholesale replace).
- Extend `test_service_component.py` with resolve-as-of-t and end-to-end
  ingest+audit through the facade.
